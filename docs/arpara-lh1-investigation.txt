原因と修正
  src/disambiguator_statebased.c の naive_classify は幅2250〜6750 ticksの
  パルスを同期候補とする。しかし走査期間にもこの幅のパルスがある。
  従来の find_relative_offset / find_inliers は直近12候補をすべて有効な
  同期と要求するため、候補への走査パルス混入でロックできなかった。
  26の初期再生で同期として整合するものは最大8/12。同期以外の位相にある
  候補だけを除く診断再生では、未変更判別機がロックした。
  入力信号の物理的な起源（距離、反射等）やUSBデコードの完全性は未確定。

  修正は12件の同期という必要な証拠を維持する。履歴を24候補に増やし、
  同期の位相・ACODE幅に整合する12件を要求する。位相/幅誤差の500 ticks
  条件、naive_classifyの幅範囲は緩めない。
  走査窓にある候補だけを無視できる。同期窓で矛盾する候補はモデルを拒否する。
  両軸とskip-bitの循環も確認し、単一位相の周期ノイズではロックしない。
  異なる複数センサーの先頭時刻が100 ticks未満の幅に収まる候補は、
  同時フラッシュとして扱い、走査と説明して捨てる位相モデルを拒否する。
  100 ticksは候補の除外を防ぐための判定であり、同期を受理する必要条件ではない。
  27では隣接センサーの走査パルスの先頭が約437 ticks離れていた。これを
  同時フラッシュと誤認するとロックが約25秒まで遅れたため、先頭の一致を
  より厳しく判定する。これは回帰テストにも含めた。
  直近12候補がすべて同期の場合はその判定を優先し、従来の起動時間を保つ。
  古い起動ノイズを余分に保持して通常Trackerの校正を遅らせる回帰は解消した。

  PropagateStateには、走査窓でも幅3000 ticks超ならセンサーごとにconfidenceを
  減らす処理があった。28センサーの正常な長い走査を受けるとconfidenceが
  出力条件を下回り、走査全体が捨てられた。位相が走査に合うパルスを幅だけで
  減点する処理を除いた。同期幅の矛盾による減点は維持する。
  26の試験修正途中では11,849測定がこの経路等で捨てられ、最終修正では31。

  時計の周回も検証し、apply_mod_offsetの周回時1 tick誤差と、周回後の参照から
  周回前の候補を評価する問題を修正した。overlap_area / RegisterSyncも周回を
  跨ぐ同期グループとセンサーの小さな順序入れ替わりに対応する。
  27には実際の32bit時計周回が1回ある。再生中のロック解除・同期幅エラーは0。

比較方法と結果
  全再生で保存設定を新しい絶対パスの --configfile へ隔離した。
  元のデバイスJSONを含む記録、派生記録、保存された配置はコミットに含めない。
  driver_playbackは記録中のOPTIONを明示的に無視する。比較ではMPFIT、
  --no-threaded-posers、GSS使用時は --no-gss-threaded を指定。
  これらのスレッド設定は比較の再現性を保つため。実機の通常動作の必須条件ではない。
  GSS=0/1それぞれで元版と修正版を比較。保存済み局配置は持ち込んでいない。
  基準版は元commitの判別プラグインを別ディレクトリでコンパイルし、同じCLI、
  同じcore、同じ他プラグインを用いた。LD_LIBRARY_PATHでcoreをその別ディレクトリに
  固定し、SURVIVE_PLUGIN_DEBUGでプラグインのロード先も確認した。
  CLIのRUNPATHだけに任せると修正版coreの場所から修正版プラグインを拾うため注意。

Orange Piでの適用とビルド（このホストでは実行していない）
  開発ホストでコミット済みブランチをbundleにし、Piへコピーする。
  git -C ~/libsurvive bundle create /tmp/arpara-lh1.bundle arpara-lh1-investigation
  コピー先: Piの ~/ArparaOpiLog/arpara-lh1.bundle
  既存checkoutと既存installは残し、別worktreeと別prefixにビルドする。

  git -C ~/libsurvive fetch ~/ArparaOpiLog/arpara-lh1.bundle \
    arpara-lh1-investigation:refs/heads/arpara-lh1-investigation
  git -C ~/libsurvive worktree add -b arpara-lh1-fix \
    ~/libsurvive-arpara-lh1 arpara-lh1-investigation
  cd ~/libsurvive-arpara-lh1
  FIX_PREFIX="$HOME/opt/libsurvive-arpara-lh1"
  cmake -S . -B build-arpara \
    -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_INSTALL_PREFIX="$FIX_PREFIX" \
    -DDO_CORE_BUILD=ON -DBUILD_STATIC=OFF -DENABLE_TESTS=ON \
    -DENABLE_survive-cli=ON -DENABLE_driver_vive=ON \
    -DENABLE_driver_playback=ON -DENABLE_driver_global_scene_solver=ON \
    -DENABLE_disambiguator_statebased=ON -DENABLE_poser_mpfit=ON \
    -DENABLE_poser_barycentric_svd=ON -DDOTNET=DOTNET-NOTFOUND
  cmake --build build-arpara --target survive-cli test-disambiguator_statebased -j2
  ctest --test-dir build-arpara -R '^disambiguator_statebased$' --output-on-failure
  cmake --install build-arpara
  ENABLE_TESTSは既存CMake仕様により初回にextrasの再生データをダウンロードする。
  全allターゲットのビルドではなく、上の必要なターゲットを指定する。

Monado LLFAの再確認
  既存Monadoのソース変更は不要。共有libsurviveのABIは変更していない。
  LD_LIBRARY_PATH付きで既存monado-serviceのlddを確認し、libsurvive.so.0が
  FIX_PREFIX/lib配下に解決されることを確認する。静的リンクならこの切替は効かず、
  FIX_PREFIX/lib/pkgconfigを使ってMonadoを別buildディレクトリに再ビルドする。
  同じ単体測定の隔離設定を使うにはXDG_CONFIG_HOME="$CAPTURE_DIR/xdg"を指定する。

  cd ~/monado
  LD_LIBRARY_PATH="$FIX_PREFIX/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
  XDG_CONFIG_HOME="$CAPTURE_DIR/xdg" SURVIVE_PLUGIN_DEBUG=1 \
  SURVIVE_GLOBALSCENESOLVER=1 SURVIVE_LH_GEN=1 SURVIVE_LOG=debug \
  LLFA_TRACKER_OVERRIDE=1 LLFA_TRACKER_IN_HMD=0,0,0,0,0,0,1 \
  XRT_TRACKING_ORIGIN_OFFSET_Y=0 XRT_COMPOSITOR_FORCE_DRM=1 \
  XRT_COMPOSITOR_DRM_DEVICE=/dev/dri/card0 XRT_COMPOSITOR_DRM_CONNECTOR=DP-1 \
  XRT_COMPOSITOR_DRM_MODE=3840x1920@90.001 XRT_COMPOSITOR_DRM_SYNC_FD=1 \
  XRT_COMPOSITOR_COMPUTE=0 XRT_COMPOSITOR_SCALE_PERCENTAGE=100 \
  XRT_COMPOSITOR_DRM_PRE_FRAME_WAIT=1 XRT_COMPOSITOR_DRM_WAKE_BUDGET_US=6000 \
  XRT_COMPOSITOR_FORCE_GPU_INDEX=0 XRT_COMPOSITOR_LOG=info \
  ./build/src/xrt/targets/service/monado-service > "$CAPTURE_DIR/monado.log" 2>&1
  元のruntime manifestとhello_xr -G Vulkanを使う。builder llfa、tracker選択、
  head assigned to arpara wrapper、実際の並進/回転、静止安定性、90Hz表示、
  正常終了時のKMS復帰を確認する。単体のsurvive-cliは終了してから起動する。
  戻すには元のprefixと元の設定で従来のMonado起動コマンドを使う。元の共有ライブラリ、
  Monado build、実機の保存設定はこの手順では上書きしない。
