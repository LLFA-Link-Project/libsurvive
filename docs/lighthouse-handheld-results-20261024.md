## 確認して修正した不具合

### native recorder の同時書き込み（`612629c`）

gzip の CRC は通るが、約 37.113 秒の 2 行に NUL と混在した timestamp／payload があった。
一方は raw IMU、もう一方は `LH_POSE` に関係する。高速回転より前の箇所であり、
この破損を手持ちジッターの原因とは断定しない。Monado JSONL writer の drop/unwritten=0 は
この同期 native writer の正常性を保証しない。

native writer は gzip ストリームを排他せず、timestamp と本文も別々に書いていた。
API 側と worker 側からの書き込みを、専用 mutex で直列化した。
CONFIG、DATA_MATRIX、FULL_COVARIANCE も本文全体を 1 レコードとして保護する。
ctx lock と独立した出力 lock とし、閉じる前に writer を終了させる既存の lifecycle は維持する。

旧 recorder ソースを使ったテストは単一 writer では成功し、4 writer では SIGSEGV。
修正版は plain/gzip の両方で ID、通番、全レコードの完全性を確認し、10 回連続成功。
同じテストは ASan/UBSan でも成功した。修正前後の最新入力全長の native POSE ハッシュは一致。
記録は引き続き同期式で、非同期 native writer の欠落統計が追加されたわけではない。

### フィルタの加速度補正の逆算（`f8886a2`）

IMU モデルが `measured = scale * acceleration + bias` なのに、補正関数は
`measured / scale - bias` だった。正しい `(measured - bias) / scale` に修正した。
倍率が 1 から離れ、bias があるときに違いが出る。
既知の加速度を forward model に通して戻すテストは旧版で失敗し、修正版で成功する。
入力と出力を同じ配列にした場合も検証した。

この修正はフィルタ推定値の逆算であり、工場較正の値や単位換算の変更ではない。
最新の手持ち区間の指標は、この修正単独ではほぼ変わらなかった。
BS 1.0／2.0 の過去の動作 2 記録も全長再生し、SteamVR 出力との held-out 比較を 50 Hz で実施した。
BS 1.0 の差分 RMSE は 5D が 62.32→62.33 mm／1.948→1.949°、
DF が 114.41→114.42 mm／2.753→2.756°、F39 が 81.31→81.30 mm／2.607→2.607°。
BS 2.0 は丸めた桁では同じ（DF 8.87 mm／2.351°、F39 8.44 mm／1.987°）。
改善の証明ではなく、モデル整合性を直す変更の影響確認である。参照出力も ground truth ではない。

## 手持ち区間の設定比較

生入力から `LH_POSE` を取り除き、新規 config、直列 poser/GSS、追加の自動床追従なしで全長再生。
元記録は変更していない。NUL を含む 2 行を評価用コピーから除外したため、完全無欠な入力の
再生ではない。欠けた raw IMU サンプルを推測して復元してはいない。
比較では full state を固定し、bias Q 以外の試行は gyro/acc bias Q=1e-8 のままにした。

下表は Tracker の 120〜125 秒。200 Hz に補間し、中心 ±0.25 秒の 101 点平均を引いた
出力変動の RMS。物理的な微小運動も含み、位置・角度の誤差 RMSE や純粋なノイズ量ではない。
この窓の最大 pose 間隔は約 8.56 ms。欠落区間の外挿はしていない。

| 条件 | 位置の変動 mm | 角度の変動 ° |
|---|---:|---:|
| 従来設定 | 0.4775 | 0.2147 |
| bias Q=0（状態次元を固定） | 0.4074 | 0.2143 |
| 静止時の速度拘束だけ無効 | 0.5223 | 0.2159 |
| 静止時の長い光学時間窓だけ無効 | 0.4774 | 0.2146 |
| 加速度逆算修正、他は標準 | 0.4775 | 0.2147 |
| 加速度逆算修正＋角速度プロセス雑音 60→0.6 | 0.4066 | 0.0980 |

角速度プロセス雑音を小さくした場合、115〜120 秒でも角度変動は 0.2478→0.2226°。
後半 1 区間だけを根拠に既定値は変更していない。過去の BS 1.0／2.0 での同設定の誤差変化は
混合しており、強く下げた 0.006 は過去の動作評価で悪化している。

センサ tick を合わせた `POSE_STATE` の quaternion 差分から体座標系の角速度を求め、
工場補正済み gyro の隣接 2 サンプル平均からフィルタ残差 bias を引いた値とも比較した。
`IMUCorrection` はこの記録・設定では恒等回転である。
120〜125 秒の両者の不一致 RMS は、0.13764→0.02989 rad/s。
bias を引いた gyro 自体の RMS は 0.04897→0.04896 rad/s とほぼ同じ。
単に bias が大きく変化したためではなく、姿勢の細かい変化が gyro と整合する方向に変わっている。
ただし、同じ推定系の内部比較であって独立した精度・実遅延の測定ではない。
高速回転でも内部不一致は小さくなるが、gyro 飽和や実際の動きを別に評価できたわけではない。

## 検証と再集計

関連 CTest 16/16。recorder と加速度補正の回帰テストは ASan/UBSan でも成功。
新しいコードで LH-Dump 全量を再評価した結果ではない。体感ジッター改善は未確認。

個別記録・ログ・コマンド・入力コピー・解析は `.lh-evaluation/handheld-2026-10-24/` に保持。
次のツールで短い記録の出力変動と gyro との内部整合性を再集計できる。
window の外側も含めて pose がカバーしない場合や間隔が 20 ms を超える場合は窓を除外する。
大回転の姿勢差を微小運動の RMS として読まないこと。

```sh
python3 tools/lighthouse_micro_motion.py \\
  .lh-evaluation/handheld-2026-10-24/acc-correction-ang0p6/record.rec.gz \\
  --window 55:80 --window 115:120 --window 120:125 \\
  --output /tmp/lighthouse-handheld-windows.json
```

`tools/lighthouse_calibration_audit.py` は NUL を含む行の件数・例も出すようにした。
該当行は除外し、隣接 pose の比較を切る。全種類の文法を検証するパーサーではない。
EOF までの gzip 検証と、native レコード自体の完全性の検証は区別する。
