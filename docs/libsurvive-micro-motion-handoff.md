# WiVRn Codex への引き継ぎ：手持ち微動中の滑り・ジッター

## 目的とユーザーの観測

完全静止では止まって見えるが、コントローラーを手に持って微動していると揺れ、
一定方向に滑り続けるようにも感じる。prediction clamp=0 msでも起きる。
SteamVR/steamvr_lh の較正をインポートせず、libsurvive 自身の推定を改善したい。
「机に固定したときのRMS低下」だけで解決扱いにしない。

ユーザーは必要なロガー移植・実測を認めている。WiVRn側の作業ツリーとAGENTS.mdを
確認して進め、libsurvive元リポジトリの未コミット作業は変更しない。

## これまでに分かったこと

- `b13c3b3` は名目250 Hzより少し速いIMUが125 Hzに間引かれる問題を修正した。
  `docs/lighthouse-cadence-results.md` 参照。これはジッター解消の証明ではない。
- 元の約48秒の静止記録では、固定100 ms予測を加えても揺れは大幅には増えなかった。
  この比較の100 msは実際のMonado予測時間ではない。
- 既存の静止判定では `move-threshold-gyro=.075 rad/s`、加速度差`.03 g`、
  光学角差`.02 rad`。手持ち微動が静止として扱われる可能性を調査中。
  単純に閾値を厳しくした試験では、BS 1.0記録で較正不能になったため採用していない。
- バイアス用ランダムウォークが別の姿勢モデルへ設定され、しかもそのモデル初期化で
  消される実装を発見した。旧実装ではバイアス共分散の期待する時間増加がゼロになる。
  `d50e4e0` で修正し、再生評価と回帰テストを実施した。短い静止記録の変化は小さく、
  動作記録では一部のRMSEが少し増えている。実機症状の原因とはまだ断定していない。
- 低い角速度プロセスノイズや強い静止時ゼロ速度更新で、保存データの静止RMSを
  減らせる。ただし微動を止める／遅らせる副作用をまだ排除できず、既定値にはしていない。

## WiVRn側でお願いしたい実装

`src/xrt/drivers/survive/survive_driver.c` の実際に利用中のコンテキストで記録する。
別プロセスのsurvive-cliを起動してUSBを取り合う方式は使わない。
既存のLighthouse recorderのwriter/clock/lifecycleを再利用できるか確認する。

1. libsurvive依存コピーを最新のローカル `llfa-main` に更新する。
   `tools/update-libsurvive-backend.sh` を利用し、実際にロードしたライブラリと
   pluginのパス・SHA-256、WiVRn/Monado/libsurviveのrevision、差分・パッチを残す。
   コピーした実行ファイルの隣にライブラリがあるだけではロード先の証明にならない。
2. 同じ実行中コンテキストでnative記録を有効にする。初期化時のlibsurvive設定として
   `record=/absolute/path/session/native.rec.gz`、`record-imu=1`、`record-cal-imu=1`、
   `record-rawlight=1`、`record-angle=1`、`record-pose-timing=1`、
   `record-tracking-state=1`、`report-in-imu=1` を渡す。
   `record-tracking-state` は `1fc8b3d` で追加済み。記録形式は本リポジトリの
   `docs/lighthouse-tracking-state.md` を参照。通常利用時の既定はOFF。
   設定はstartup前に適用し、記録経路だけを変えて推定設定を暗黙に変更しない。
3. backendが受け取る予測前の姿勢・速度と、Monadoのrelation historyへ入れる値、
   アプリ要求に対する予測／オフセット合成後の姿勢を区別してJSONLへ記録する。
   左右はcodenameから決めず、実行中のroleとserialを保存する。
   各行にserial、段階、monotonic callback時刻、センサーtickとHz（分かる段階）、
   姿勢時刻、pose/velocity各時刻、位置m、向きxyzw、線速度m/s、角速度rad/s、
   validity、座標系・参照点、要求時刻と実効予測時間を付ける。
   計測できない値はnullにし、取得時刻をセンサー時刻に見せない。
   INPUT_TIMEが対応するPOSE行より後になる場合もあるため、行順や異なる時計の差を
   そのまま入力から出力までの遅延と解釈しない。
4. IMU原点でのpose/velocity、world変換、head/grip/palm変換、floor offsetを保存する。
   clamp=0 msでは実効追加予測も0 msであることを確認する。
   生のIMU角速度とKFの残留gyro biasは単位・座標を合わせて解析する。
5. writerのキュー容量・投入/書込/drop数と終了状態を保存する。
   追加するWiVRn側writerはpose callbackをディスクI/O待ちにしない。通常の終了時にstop/join/flushし、
   manifestにraw入力・設定snapshot・シーン区間・完全性とSHA-256を残す。
   起動時の任意の診断設定として実装し、余分な常時ポーリングやUI操作を増やさない。

native recorder自体は現在同期式で、独立したdropカウンターを持たない。
その負荷・flush/書込エラーの確認範囲を明記し、取得不能な指標はnullにする。
計測を有効にした場合の挙動と、通常利用のジッターを混同しない。

libsurvive内部のtracker構造体をMonado側から直接参照する必要はない。
native記録の `POSE_STATE` / `POSE_BIAS` / `POSE_BIAS_VAR` と時刻・serialを突合する。
未対応のライブラリでは診断が取れないことを明記し、空データを成功扱いにしない。

## 実測手順

同じ最新バイナリ（`d50e4e0` と `1fc8b3d` を含む）で次の設定だけを比較する。

| 設定 | A：旧実装の有効な挙動を再現 | B：修正後 |
| --- | --- | --- |
| `kalman-minimize-state-space` | `0` | `0` |
| `process-weight-gyro-bias` | `0` | `1e-8` |
| `process-weight-acc-bias` | `0` | `1e-8` |

両方でfull stateを明示する。Aのbias process weightを0にした際に、自動の次元削減が
別の変数まで変えてしまうのを防ぐ。現在の通常の既定値でも有効なモデルは同じfull state。
Aの0はbiasの時間変動の比較であり、IMU入力・静止時bias推定は引き続き利用する。
このA設定は保存済み静止記録で旧実装の姿勢ストリームと完全一致し、Bのfull-state指定も
通常の修正版と完全一致することを確認した。BS 1.0/2.0の2つの動作記録でも、A制御が旧実装の姿勢ストリームと完全一致することを確認した。

ロガーは同条件とし、強い平滑化・ZVU変更・静止閾値変更を同時に加えない。
各条件の実行バイナリと設定を保存する。今回は角速度プロセスノイズを変える追加候補は
まだ適用しない。`docs/lighthouse-jitter-trials.md` に探索結果と制約をまとめる。

- まずclamp=0 ms。A→B→Aの順で、BS・照明・置き方・左右役割を維持する。
- 各実行は専用の新しい較正設定ファイルでlibsurvive自身に較正させる。
  USB機器の工場出荷時intrinsicsは利用してよい。ValveのBS外部姿勢は入れない。
- 起動後30〜60秒の較正・ウォームアップを残し、開始直後を静止評価と混ぜない。
- 机上完全静止20秒。その後、肘を支えて手持ち微動20〜30秒。
- 向きをほぼ保った数mm〜1cmのゆっくりした移動と、±1〜3度のゆっくりした回転を
  各20〜30秒。静止判定のON/OFFと動き出し・反転の時刻を確認する。
- 通常の手の動作・速い往復20秒。最後に静止へ戻り20秒。
  区間名と開始/終了monotonic時刻を記録する。動きの振幅・速さは目標値と明記し、
  手動で動かした距離を実測の真値にしない。
- 短い遮蔽や復帰も追加できれば記録する。欠測・復帰時の大きな飛びを平滑化で隠して
  「静止ジッターが良い」と評価しない。

完全静止区間のgyro平均は残留biasの診断に使える。一姿勢での静止加速度だけから、
重力方向と全軸bias/scaleを独立に決めたことにはしない。
手持ちの微動をゼロ角速度として校正し続ける処理は、比較記録が揃う前には追加しない。
既存の静止判定が微動を静止扱いし、実際の角速度をbiasとして学習していないかを
A/Bで確認する。修正版を症状が直った実用設定として無条件に適用しない。

## 返してほしいもの

変更コミット／適用パッチ、ビルド・ロード先の証拠、各セッションの保存先、
設定snapshot、区間表、drop/終了結果を短い引き継ぎ書へまとめる。
解析は予測前の微動追従を主対象に、姿勢の滑る方向、gyro平均とbias差、
静止判定の継続時間、光学/IMU更新の鮮度、raw姿勢と描画姿勢の差を確認する。
tracking lossや再初期化の前後で推定biasがゼロへ戻るかも確認する。
静止RMSだけでなく動作中の遅れ・反転の追従と、更新頻度を示す。
現時点で原因は未確定とし、追加予測の無効化や外部較正インポートを解決策にしない。
