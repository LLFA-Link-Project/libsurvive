# WiVRn への較正・微小運動調査の返答（2026-10-24）

対象実装: libsurvive `4def8c2`。読み込んだ WiVRn 側資料は
`docs/libsurvive-micro-motion-implementation.md` と
`docs/libsurvive-calibration-failure-handoff-20261024.md`。
外部の基地局姿勢は使用していない。既存の良好な初期値も libsurvive 自身の較正である。

## 今回確定したこと

- 19:34・19:36 の生入力を、記録された `LH_POSE` を除いて最後まで再生した。
  初期値なし／良好な自己較正／19:36 の不良初期較正と、バイアス Q=0／1e-8 を比較。
  両 Q とも `kalman-minimize-state-space=0`、同一バイナリ、直列実行、追加の床追従なし。
- 不良初期値では Q=0 でも数十 m 級の位置と繰り返す tracking reset を再現した。
  バイアス Q の追加がなくても発生する。ただし、Q があらゆる状況で無関係だとは証明していない。
- 初期値なしの直列再生では、今回の実測と同じ悪い初回較正は再現しなかった。
  19:34 の実時間・GSS と poser の両ワーカー有効の 3 回の再生でも同じ悪解は再現していない。
  実測のスレッド順序、初回採用シーン、ロガー負荷まで再現できたとはいえない。
- 19:34 の 100 秒超の callback と simple API pose-time の差は、すべて logger が
  **無効姿勢**とした行だった。有効姿勢の差は約 −2.4〜+6.8 ms。
  未初期化の `OutPose_timecode=0` を現在のセンサ時刻の対応式に入れると、
  センサ起動時付近の時刻になる。この差を有効追跡の実遅延／発散原因として扱わない。
  19:36 の有効姿勢には最大約 251 ms の差があるため、更新途絶などの確認は別途必要。

## 急角度の基地局設置と品質指標

BS の取り付け角を制限する変更はない。
新しい診断は **基地局の局所座標で観測した加速度を推定姿勢で世界座標に移し、
世界の重力軸との角度を測る**。装置が強く傾いていても、対応する姿勢推定が正しければ
誤差はゼロになる。0〜180°の傾きと追加の別軸回転を組み合わせた単体テストを追加した。

重力だけの半球判定による棄却と、それを使った再初期化は試作したが**採用していない**。
不良ファイルからの復帰は改善せず、保存禁止だけでも実用追跡には戻らなかった。
旧評価由来の 117 ログにある 852 基地局結果には反対半球の例はなかったが、
これは新方式による全量再評価でも、あらゆる設置・機種での保証でもない。

今後の判定では、光学的な説明誤差、物体と BS それぞれの重力整合性、
静止／移動判定の確からしさ、時系列の IMU と光学更新の整合性を区別して使う。
最適化に投入した観測への適合だけで正解とはいえない。
採用していない別時刻・別シーンの光学観測でも説明できるかを検証し、
良好な BS 1.0／2.0 の記録と手持ち微小運動の両方で誤棄却を確認してから閾値を決める。
今回の 1 件から角度、位置ジャンプ、共分散の合否閾値を決めてはいない。

## 実装済みの診断修正

`handle_accel_meas` の `object_up_error` は `(ex+ey+ez)^2` だったため、
異なる軸の誤差が相殺していた。`ex^2+ey^2+ez^2` に修正した。
この古い名前の集計には物体と BS の両方の加速度拘束が含まれる。
過去の `up err` と新しい `up err` の数値をそのまま比較しないこと。
最適化の残差・ヤコビアンはこの変更では変えていない。

診断用 `survive_optimizer_current_norm` も、観測ブロック数で残差バッファを確保していた。
加速度や位置のような 3 次元観測では足りず、ノルムの集計も不足していた。
残差の次元数を使い、無効観測の領域をゼロ初期化するよう修正した。
今回調べた通常の追跡経路はこの診断 API を呼んでおらず、発散原因を直したとの主張はしない。

`record-tracking-state=1` のときは、**失敗を含む**各 GSS 最適化の後に以下も native の
`INFO LOG` と通常ログへ出る。入力の再生には使わず、合否判定にも使わない。

```
GSS_QUALITY status=... scenes=... optical_rms_rad=... optical_count=... object_gravity_rms_deg=... object_gravity_count=...
GSS_LIGHTHOUSE_GRAVITY index=... channel=... angle_deg=...
```

`optical_rms_rad` は既存 solver の光学残差統計、物体の角度 RMS と BS の角度は
最適化から戻った姿勢と観測重力から計算する。光学値は fit に使った観測の統計であり、
未使用観測に対する誤差ではない。欠落した重力の角度は `nan`（ゼロ誤差ではない）。
最適化 status が失敗の候補も含むため、出力行自体を「採用済み」の意味で読まないこと。

## 比較に使う設定の固定

調査中に 19:54 の追加実測記録を発見した。修正済みの正しい設定パスを使っており、
その実測が動いている間に元の設定ファイルも更新されていた。
初期の探索では現在の設定をコピーしていたため、一部の良好初期値の比較には異なる
floor offset が混じった。これらは同一入力の出力ハッシュ比較から除外した。

最終の良好初期値の比較は、19:54 記録内の変更されない `calibration.initial.json` を
評価用フォルダへ固定コピーし、各試行でも初期 snapshot と SHA-256 を保持して再実行した。
元の設定／記録への書き込みは行っていない。失敗した初期値と新規較正の試行も、
それぞれ専用の config と出力を使用した。

集計と除外指定: [評価結果](lighthouse-calibration-failure-results.json)。
個別の native 記録、コマンド、ログ、依存ライブラリの SHA と解決先は
`.lh-evaluation/calibration-failure-2026-10-24/` にある。
新しいコードによる全 LH-Dump の再生ではない。

## WiVRn 側で次に行うこと

1. libsurvive を `4def8c2` 以降へ更新し、実際に読み込んだ core/plugin のパスと SHA を保持する。
   既存ロガーの `record-tracking-state=1` で新診断も記録される。予測・フィルタ設定は変えない。
2. 良好な自己較正を固定 snapshot として保存し、各試行に同じ snapshot をコピーする。
   新規較正の試行は別の絶対 config パスで行い、普段使う設定を上書きしない。
   live に更新される設定を試行ごとに読み直す比較は避ける。
3. まず良好初期値と新規較正で正常に追跡できるかを分離して記録する。
   新規較正に失敗した場合は、新しい GSS 診断と前後の `I`、`POSE_STATE`、bias、pose-time を保存。
   `finite`／logger の `pose_is_valid` だけで、較正品質が十分だとは判定しない。
4. 較正が良好な状態で [微小運動の手順](libsurvive-micro-motion-handoff.md) を実施する。
   剛体静止・手持ち微小運動・ゆっくりした移動を区切り、Q の比較では完全な状態次元も固定する。
   手持ちの本当の微小回転を gyro bias として学習していないかを確認する。

最初の新規較正失敗の原因は引き続き未確定。次に必要なのは、失敗時に実際に GSS が
採用したシーン・観測集合・初期値を固定して再実行できる記録である。
通常の raw-input 再生だけでは、スレッド間のシーン選択順序が一致する保証はない。
`serialize-lh-mpfit` の現行形式も加速度等の観測種別を完全には保存しないため、
そのまま完全再現用 snapshot と見なさないこと。

関連 15 CTest は成功。新しい回帰テストは ASan/UBSan でも成功。
棄却したガード試作版による不良初期値の全長 ASan 再生は 300 秒で timeout しており、
全長 sanitizer 成功としては数えていない。剛体静止・手持ちの体感ジッター改善や
新規較正失敗の解消を確認したという結果ではない。
